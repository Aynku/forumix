Es läuft schon eins

Auf forum.forumix.de läuft Forumix selbst — dieselbe Fassung, die hier zum Herunterladen steht. Anmelden, schreiben, ausprobieren. Und wenn beim Aufsetzen etwas klemmt, fragst du genau dort.

🔎 Zum Ausprobieren

  • Kein Video und kein Bilderbuch, sondern die laufende Software.
  • Registrieren, Beiträge schreiben, Themen abonnieren, Benachrichtigungen bekommen.

💬 Zum Fragen

  • Installation, nginx-Direktiven, eigene Anpassungen.
  • Fehler melden — im Forum oder als Issue im Repository.

Nichts, was nach Hause telefoniert

Forumix ruft im Auslieferungszustand keinen fremden Server auf. Keine Schriften von Google, keine Skripte von einem CDN, kein QR-Dienst für die Zwei-Faktor-Einrichtung, keine Rückmeldung an den Hersteller.

Schriften liegen lokal

  • Sieben Familien mitgeliefert, latin und latin-ext. Kein Aufruf bei fonts.googleapis.com, also keine Besucher-IP in fremden Protokollen.

QR-Code selbst erzeugt

  • Der Code für die Zwei-Faktor-Einrichtung entsteht auf dem eigenen Server. Der Schlüssel verlässt die Maschine nicht.

Editor selbst gehostet

  • Auch der Code-Editor im Adminbereich kommt aus dem eigenen Verzeichnis, nicht von einem Content-Netzwerk.

Herunterladen

Ein Archiv, entpacken, hochladen. Darin ist alles enthalten — auch die Schriften und der Editor, es wird nichts nachgeladen.

forumix-0.21.0.zip Vollpaket · neue Installation · entpacken und hochladen
forumix-update-0.21.0.zip Update · von 0.18.58 · Adminbereich → Updates

SHA-256 zum Nachrechnen: forumix-0.21.0.sha256
sha256sum -c forumix-0.21.0.sha256

Das Update-Paket enthält nur die geänderten Dateien und wird im Adminbereich unter Updates hochgeladen — kein FTP, kein Überschreiben von Hand. Die config.php und alles unter uploads/ bleiben dabei unberührt.

Installation

Kein Composer, kein Node, kein Build-Schritt. Es reicht ein Webspace mit PHP und MySQL, ein FTP-Programm und zehn Minuten.

  1. Datenbank anlegen

    Im Kundenmenü deines Hosters — bei Plesk, cPanel oder Confixx heißt der Punkt meist „Datenbanken". Leere Datenbank anlegen, Benutzer dazu, und die vier Angaben notieren: Host (fast immer localhost), Name, Benutzer, Passwort. Als Zeichensatz utf8mb4 wählen, falls gefragt wird.

  2. Dateien hochladen

    Das Archiv auf dem eigenen Rechner entpacken. Dann den Inhalt des Ordners forumix-x.y.z/ per FTP in das Web-Verzeichnis schieben — je nach Hoster heißt das httpdocs, public_html, htdocs oder www. Nicht den Ordner selbst hochladen, sonst liegt das Forum später unter /forumix-x.y.z/.

  3. Installer aufrufen

    Im Browser https://deine-domain.tld/install/ öffnen. Er prüft zuerst PHP-Version, Erweiterungen und Schreibrechte und sagt dir im Klartext, was fehlt. Danach fragt er die vier Datenbank-Angaben ab, legt die Tabellen an und zuletzt dein Inhaber-Konto.

  4. Ordner install/ löschen

    Per FTP, gleich im Anschluss. Der Installer sperrt sich nach getaner Arbeit zwar selbst und antwortet nur noch mit 403 — aber weg ist gründlicher als zu.

Wenn der Installer über Schreibrechte klagt: er legt zum Schluss die config.php im Hauptverzeichnis an und braucht dafür Schreibzugriff. Auf den meisten Webspaces passt das von allein. Wenn nicht, im FTP-Programm einen Rechtsklick auf den Ordner → Dateirechte → 755, bei manchen Hostern 775. Dasselbe gilt für uploads/, sonst lassen sich später keine Avatare hochladen.
Läuft dein Server mit nginx statt Apache, brauchst du ein paar Regeln im Server-Block: nginx liest .htaccess nicht, und zwar ohne Fehlermeldung. Ohne diese Regeln sind Vorlagen, Sicherungen und der Übersetzungs-Cache von außen erreichbar. Der fertige Block steht in der README des Pakets. Auf einem normalen Webspace mit Apache musst du nichts tun.
