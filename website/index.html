Ein vollständiges Forum.
Ohne alles, was man sonst mitschleppt.

Forumix ist Forensoftware in nativem PHP — kein Composer, kein Framework, kein Build-Schritt. Hochladen, Installer aufrufen, fertig.

Quelltext ansehen Installation
PHP 8.1+ MySQL / MariaDB keine Abhängigkeiten AGPLv3

Was drin ist

Kein Grundgerüst, das man erst mit Erweiterungen brauchbar macht. Was ein Forum braucht, ist eingebaut.

💬 Inhalte

  • Kategorien, Foren, Themen, Beiträge
  • BBCode mit Zitat-Sprung zum Original
  • Umfragen, auch mit Mehrfachauswahl
  • Datei-Anhänge und Bilder
  • Tags, Lesezeichen, Abos
  • @Erwähnungen mit Vorschlagsliste
  • Passwortgeschützte Foren
  • Private Nachrichten

👥 Mitglieder

  • Profile mit Banner, Avatar, Signatur
  • Ränge nach Beitragszahl
  • Achievements und Aktivitätskarte
  • Wer ist online, inklusive Bot-Erkennung
  • Zwei-Faktor-Anmeldung mit Backup-Codes
  • Angemeldet bleiben über geteilte Token
  • Selbstlöschung des Kontos

🛡️ Moderation

  • Inhaber, Admins, globale und Forum-Moderatoren
  • Freigabe je Forum für Themen und Antworten
  • Meldungen mit Bearbeitungsstand
  • Verwarnungen mit automatischer Sperre
  • Bearbeitungsverlauf je Beitrag
  • Moderationsprotokoll
  • IP-Sperren

🎨 Aussehen

  • Farben, Schrift und Abstände im Adminbereich
  • Hell und dunkel, vom Mitglied wählbar
  • Logo entsteht aus dem Forum-Namen
  • Eigene Vorlagen mit Auto-Escape
  • Sieben Schriften, alle selbst gehostet

🔐 Sicherheit

  • Durchgehend vorbereitete SQL-Anweisungen
  • CSRF-Token an jeder schreibenden Aktion
  • bcrypt, Sitzungserneuerung beim Login
  • Bremsen für Login, Registrierung, 2FA
  • Dreistufiges Captcha
  • Content-Security-Policy ab Werk

⚙️ Betrieb

  • Sicherungen für Datenbank und Dateien
  • Update-Pakete mit Prüfung vor dem Einspielen
  • Migrationen aus dem Adminbereich
  • Wartungsmodus
  • Modulsystem für Erweiterungen
  • Eigene Seiten für Impressum und Datenschutz

Nichts, was nach Hause telefoniert

Ein Forum ruft im Auslieferungszustand keinen fremden Server auf. Keine Schriften von Google, keine Skripte von einem CDN, kein QR-Dienst für die Zwei-Faktor-Einrichtung, keine Rückmeldung an den Hersteller.

Schriften liegen lokal

  • Sieben Familien mitgeliefert, latin und latin-ext. Kein Aufruf bei fonts.googleapis.com, also keine Besucher-IP in fremden Protokollen.

QR-Code selbst erzeugt

  • Der Code für die Zwei-Faktor-Einrichtung entsteht auf dem eigenen Server. Der Schlüssel verlässt die Maschine nicht.

Editor selbst gehostet

  • Auch der Code-Editor im Adminbereich kommt aus dem eigenen Verzeichnis, nicht von einem Content-Netzwerk.

Installation

Datenbank anlegen, Dateien hochladen, Installer aufrufen. Kein Composer, kein Node, kein Build.

  1. Datenbank anlegen

    Eine leere Datenbank und ein Benutzer, der nur darauf Rechte hat.

    CREATE DATABASE forum CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'forum'@'localhost' IDENTIFIED BY 'starkes_passwort';
GRANT ALL ON forum.* TO 'forum'@'localhost';
  2. Dateien hochladen und Rechte setzen

    Inhalt des Pakets in das Web-Verzeichnis, dann drei Ordner beschreibbar machen.

    chmod 775 cache/templates uploads uploads/avatars uploads/attachments
  3. Installer aufrufen

    Vier Schritte: Voraussetzungen, Datenbank, Schema, Inhaber-Konto. Danach den Ordner install/ löschen.

    https://deine-domain.tld/install/
# nach Abschluss:
rm -rf install/
Unter nginx müssen ein paar Regeln in den Server-Block, weil nginx keine .htaccess liest — ohne sie sind Vorlagen, Sicherungen und der Übersetzungs-Cache von außen erreichbar. Der fertige Block steht in der README des Pakets, samt Befehlen zum Nachmessen.
